# 신규 API 응답·스키마 확인 결과 (2026-10-20 실제 호출)

호출 방법: 서비스키 + `returnType=json`, `numOfRows=100`, `pageNo`, 선택 `safety_cate`. 키 값은 기록하지 않았고 응답 원본은 `data/fixtures/probe/`(git 제외)에 저장했다.
4종 모두 HTTP 200, `resultCode: "00"`.

## 1. 공통 응답 봉투
```json
{"header": {"resultMsg": "NORMAL SERVICE", "resultCode": "00", "errorMsg": null},
 "numOfRows": 100, "pageNo": 1, "totalCount": 40, "body": [ ... ]}
```
- 오류는 HTTP 200에 `header.resultCode`가 `00`이 아닌 값으로 올 수 있다(기존 소스와 동일한 가정, 신규 4종에서 오류 응답은 아직 확인하지 않음).
- 한 페이지 상한 100행. `totalCount`가 상한을 넘으면 다음 페이지를 요청한다.

## 2. 행동요령 계열 3종 (사회재난·생활안전·민방위) — 기존 자연재난(20588)과 **스키마 동일**

|---|---|---|
| `actRmks` | 문자열 또는 null | 행동요령 본문(관측 최대 423자). 1,466행 중 91행이 null |

| `safety_cate2` / `safety_cate_nm2` | 문자열 | **재난 유형** 코드·이름 (5자리, 예 02011 화재) |

- 같은 어댑터로 소스 이름만 바꿔 처리할 수 있다 → ADR-013의 `guide` 어댑터 후보 확인.
- 이름 필드 `safety_cate_nm4`는 응답에 없다.

### 호출 규칙 (기존 자연재난과 같음)
- `safety_cate` 없이 호출하면 **첫 유형만** 돌아온다 (민방위 04001 비상사태 40행, 생활안전 03002 응급처치 55행, 사회재난 02001 해양오염사고 16행).
- `safety_cate`에는 **대분류(02 등)가 아니라 유형 코드(02011 등)**를 넣어야 한다. 대분류 코드는 0행.
- 유형 코드는 연속 번호이지만 빠진 번호가 있다 (생활안전 03001 없음, 03018 이후 없음 — 상한은 030까지 확인).

## 4. 데이터 품질·사용 시 주의
- **차량 침수 탈출 지침은 없다.** "차량·자동차·침수·지하차도·운전·목받침·망치" 키워드를 1,466행에서 검색했을 때 침수 + 차량이 함께 나오는 행은 0건, 지하차도·목받침은 0건이었다. 차량 관련 행은 교통사고·테러·가축질병 등 다른 맥락이다. → 해당 질문은 "공식 데이터에 없음"으로 답하는 것이 맞다.
- **대상이 일반 시민이 아닌 행이 섞여 있다.** 예: 교통사고 유형의 "차량에서의 구조" 단계(19행)는 구조대원 작업 지침("현장통제를 구축한다", "차량을 전개한다"), 테러 유형의 식별요령 49행, 가축질병·산불 가축관리 등. 기존 `judge`의 `NICHE_WORDS` 뒤로 미루기만으로는 부족하다 → 대상(시민/전문가)에 따른 선택 규칙이 필요.
- 서술 형식이 섞여 있다. 사회재난 일부는 `Q : … A : …` 형태 한 덩어리이고, 일부는 `○`·`-`로 시작한다. 정규화(앞의 `-` 제거 등, 기존 `load_guide`와 같은 처리) 필요.
- 본문에 금지 표현이 들어 있을 수 있다(기존 T-024). 신규 소스도 같은 검사를 통과시켜야 한다.
- 일반 시민 안전 질문과 거리가 먼 유형이 많다(금융전산, 원전, 테러, 민방공 등). MVP 연결 후보는 `hazard_map`의 특보 유형과 이어지는 것 위주로 제한한다.

## 5. 통합대피소 (DSSP-IF-10941)
| 필드 | 타입(관측) | 설명 |
|---|---|---|
| `REARE_NM` | 문자열 | 시설명 |
| `RONA_DADDR` | 문자열 | 도로명 전체 주소 |
| `LAT` / `LOT` | 숫자(float) | 위도 / 경도 |
| `SHLT_SE_CD` | 문자열 | 대피소 구분 코드 ("1"~"4") |
| `SHLT_SE_NM` | 문자열 | 구분 이름 (복합 표기 있음) |
| `MNG_SN` | 문자열 | 관리 일련번호 |
- 요청 파라미터: `startLat`, `endLat`, `startLot`, `endLot`(위경도 범위), `shlt_se_cd`(구분).
- 총 76,787건. 구분별 총계: 1(한파쉼터) 53,097 · 2(한파·무더위쉼터) 62,507 · 3(지진옥외대피장소) 10,795 · 4(지진옥외·지진해일 대피장소) 647. 구분 이름이 쉼표로 이어진 복합 표기("한파쉼터,무더위쉼터")라 구분 코드와 이름을 1:1로 보면 안 된다.
- **호우·태풍·대설용 대피소 구분은 없다.** 폭염·한파 쉼터와 지진 대피장소만 해당.
- 위경도 범위 조회는 동작한다. 데모 지역 범위(대략 값)로 조회: 광주광역시 2,064건, 경기도 광주시 범위 836건. 다만 **사각형 범위는 행정구역과 다르다** — 경기도 광주시 범위에 인접한 하남시 시설이 섞여 나왔다. 정확한 구역은 주소(`RONA_DADDR`)로 한 번 더 걸러야 한다.
- 광주광역시 주소가 **"전남광주통합특별시 …"** 로 나온다(T-009의 명칭 변경 현상과 같음). 주소 필터는 신구 명칭을 함께 다뤄야 한다.
- 안전 책임 주의: 쉼터 운영 여부·운영 시간은 응답에 없다. "가까운 곳으로 가라"로 단정하지 않고 "공식 목록에 있는 장소"로만 안내해야 한다.

## 6. 결론: 소스 상태 제안 (ADR-013 기준)
| 소스 | 제안 | 이유 |
|---|---|---|
| 사회재난 / 생활안전 / 민방위 행동요령 | `evaluating` | 스키마·호출은 확인 완료. 이용허락 확인, 대상(시민/전문가) 선택 규칙, `hazard_map` 연결 범위가 정해지면 `active` |
| 통합대피소 | `evaluating` | 폭염·한파 쉼터와 지진 대피장소 한정. 이용허락과 안내 방식 결정 전 서비스 응답에 사용하지 않음 |

## 7. pydantic 모델 초안 (경계 검증용, 코드 반영은 코드 세션)
```python
from pydantic import BaseModel, Field

class Header(BaseModel):
    resultCode: str
    resultMsg: str | None = None
    errorMsg: str | None = None

class GuideRow(BaseModel):            # 행동요령 4종 공통
    actRmks: str | None = None
    contentsUrl: str | None = None
    safety_cate1: str
    safety_cate_nm1: str | None = None
    safety_cate2: str
    safety_cate_nm2: str | None = None
    safety_cate3: str | None = None
    safety_cate_nm3: str | None = None
    safety_cate4: str | None = None

class ShelterRow(BaseModel):
    REARE_NM: str
    RONA_DADDR: str
    LAT: float
    LOT: float
    SHLT_SE_CD: str
    SHLT_SE_NM: str
    MNG_SN: str

class Envelope(BaseModel):            # 제네릭으로 body 타입만 바꿔 재사용
    header: Header
    numOfRows: int
    pageNo: int
    totalCount: int
    body: list | None = None
```
