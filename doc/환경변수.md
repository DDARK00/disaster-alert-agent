## 전환 상태 (2026-10-20 코드 반영)
1. 키 이름의 단일 기준은 `data/sources.yaml`의 `env`/`env_legacy`. `capture.service_key()`가 새 이름 → 옛 이름 순으로 읽고, 옛 이름을 쓰면 **이름만** 경고 1회(값은 남기지 않음).
2. `docker-compose.yml` mcp 서비스는 새 이름 7개 + 옛 이름 2개(전환 기간)를 넘긴다. 전환이 끝나면 옛 이름 줄과 `env_legacy`를 지운다.
3. `.env` 인라인 주석은 공백 1칸 이상 + `#`로 잘린다(T-029). 값 안의 `#`(공백 없이 붙은 것)는 그대로.
4. 키 미설정이면 호출하지 않고 원인 `api_auth_error`(ADR-014). 키 값이 로그·fixture·문서에 남지 않는지 마스킹 검사를 유지한다.

## 기타 환경변수
LangSmith(`LANGSMITH_*`), LLM(`LLM_*`), 카카오(`KAKAO_REST_API_KEY`, mcp 전용), 데이터 모드(`DATA_MODE`), 포트(`FRONTEND_PORT`)는 `.env.example` 참고.

## 시연용 장애 주입 (`DEMO_FAULTS`, 기본 꺼짐)
- `DEMO_FAULTS=1`이면 백엔드가 요청의 `fault`(`mcp_down` · `alert_tool_error` · `shelter_down`)를 받아 원인별 "정보 없음" 문구를 보여 주고, `/scenarios`에 장애 시나리오 3개가 나타난다(ADR-021).
- 기본값은 꺼짐이며 `.env.example`에 넣지 않는다. `docker-compose.yml`은 셸 값을 넘기기만 한다(`${DEMO_FAULTS:-0}`, 기본 꺼짐, ADR-022). 꺼져 있으면 `fault`가 붙은 요청은 404다. 공개 배포에서는 켜지 않는다.
- 켤 때(로컬 개발): `DEMO_FAULTS=1 LLM_BACKEND=fake sh/run_local.sh`
- 켤 때(도커, 녹화용): `DEMO_FAULTS=1 docker compose up -d backend` → 화면 "개발자 보기"의 오류 주입 선택이 활성화된다. 끝나면 `docker compose up -d backend`로 다시 끈다.
