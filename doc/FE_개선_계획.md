# 프론트 개선 계획 (6차, 시연용)

작성 2026-10-21. 브랜치 `feat/frontend-demo`. 대상: `frontend/index.html` 한 장 (바닐라 JS 유지, 빌드 없음).
목적: 5분 발표·GIF 녹화에서 ① 파이프라인이 **판단 → 근거 → 빠른 답 → 최종 답** 순으로 진행되는 모습, ② 공식 근거 중심 답변이 한눈에 보이게 한다.

## 1. 방향 — "공공 안전 표지"

이 서비스의 화면은 재난 상황에서 **지금 무엇을 할지**를 읽는 곳이다. 그래서 장식이 아니라 도로·재난 표지판의 어휘에서 고른다.
- 위험 수준은 기상청 특보 관행의 색(주의보 노랑, 경보 빨강)을 **넓은 띠**로 보여 준다. 화면에서 가장 크고 굵은 글자는 이 판정 한 줄뿐이다.
- "정보 없음"은 회색 빗금 — 공사·통제 구간 표지처럼 "모름"이 "안전"으로 읽히지 않게 한다 (기존 규칙 유지).
- 공식 근거는 공공 표지 파랑. 답변 속 `[E1]`·`[G3]`는 파란 번호표이고, 누르면 오른쪽 근거 줄이 강조된다.
- 진행 표시는 노선도처럼 네 정거장을 잇는 한 줄. 단계가 끝날 때마다 정거장이 채워지고 그 아래에 그 단계에서 확정된 내용이 한 줄로 붙는다.

대담함은 **판정 띠** 한 곳에만 쓴다. 나머지(근거 목록, 답변 본문, 입력)는 조용하게 둔다.

## 4. SSE 이벤트 → 화면

| 이벤트 | 화면 |
|---|---|
| `start` | 노선도 초기화, 판단 정거장 진행 중 |
| `route` `intent` `location` `plan` `source` `step` `validation` | 개발자 보기의 배지·시간 줄 (일반 화면에는 안 보임). `location`이 모호하면 판단 정거장 아래에 후보 이름 표시 |
| `progress` | 노선도 아래 한 줄 문구. `source_failed`면 회색 빗금 표시 |
| `judgement` | **판단** 완료 — 판정 띠(지역·수준·기준 시각). 지역이 여럿이면 띠가 지역 수만큼 |
| `evidence` | **근거** 완료 — 오른쪽 근거 칼럼 채움, 정거장 아래 "특보 n · 행동요령 n · 쉼터 n · 정보 없음 n" |
| `quick` | **빠른 답** 완료 — 답변 칼럼에 검증 통과한 기본 요약 표시, "AI 답변을 작성·검증하는 중" 꼬리표 |
| `token` | 빠른 답이 없을 때만 본문에 흘려 씀 (기존 동작 유지) |
| `final` | **최종 답** 완료 — AI 답변이 통과하면 본문 교체 + "AI 답변 · 검증 통과", 아니면 "기본 요약 유지(AI 답변이 검증을 통과하지 못함)". 고정 안내 경로(위급·되묻기·범위 밖·정보 없음)는 판단·근거·빠른 답을 "해당 없음"으로 건너뛰고 판정 띠 자리에 칩을 보인다 |
| `error` | 최종 답 정거장 빗금 + "정보 없음 — 답변을 만들지 못했습니다" |

고정 안내 칩: `not_in_data`·`unavailable` → **정보 없음**(빗금), `emergency` → **위급 — 119·112**(빨강), `ask_region` → **지역 확인 필요**, `out_of_scope` → **재난·특보 밖 질문**.

## 5. 같이 고치는 것 (이전 QA 1~3)

1. **실패 문구의 내부 소스명** — 진행 문구가 `경기도 광주시 행정안전부 긴급재난문자 (DSSP-IF-00247) 정보 없음 — …`처럼 API 이름·ID를 보인다. 원인: `backend/agent/graph.py`가 `progress_failed`에 MCP의 소스 이름을 그대로 넣음. → 백엔드에서 사용자 말("기상특보"/"재난문자")로 바꾼다. 원래 이름은 `source` 이벤트(개발자 보기)에만 남는다. 관련 단위 테스트만 다시 돌린다.
2. **노드별 시간 줄** — 일반 화면에서 숨기고 `개발자 보기` 토글을 켰을 때만 보인다 (토글 상태는 `localStorage`, 실패해도 꺼짐으로 동작).
3. **들여쓴 `- ` 불릿** — 앞 공백을 허용해 목록으로 렌더링하고, 들여쓴 줄은 한 단계 안쪽 목록으로. `▶ 지금 할 일` 같은 묶음 제목 줄은 소제목으로.

## 6. 시연용 오류 주입 토글

- 개발자 보기 안에 "오류 주입" 선택(없음 / 데이터 서비스 연결 실패 / 특보 조회 오류 / 쉼터 목록 실패). 목록은 `/scenarios`에서 `fault`가 붙은 항목으로 만든다 — 서버가 `DEMO_FAULTS=1`일 때만 오므로, 꺼져 있으면 선택이 비활성이고 "서버에서 꺼져 있음"으로 표시. 공개 서버에 장애 경로를 새로 만들지 않는다 (ADR-021 그대로).
- 도커에서 켜려면: `docker-compose.yml` backend에 `DEMO_FAULTS: ${DEMO_FAULTS:-0}`을 추가 (기본 꺼짐 유지). 녹화 시 `DEMO_FAULTS=1 docker compose up -d backend`.

## 7. 가정 (질문 대신 기본값으로 정함)

- 웹폰트는 Google Fonts에서 받는다. 오프라인이면 시스템 고딕으로 떨어지고 레이아웃은 그대로다.
- 데이터 모드(replay/live)·기준 시각 입력은 개발자 보기로 옮긴다. 시나리오 버튼이 값을 채우므로 녹화 흐름은 같다. 기준 시각은 판정 띠에 항상 보인다.
- 일반 화면에는 시간(ms)을 하나도 보이지 않는다 (정거장에도 안 붙임). 
- 개발자 보기 토글은 화면 상단 오른쪽 한 곳.
- 시나리오는 21개까지 늘 수 있어 한 줄 가로 스크롤(모바일)·줄바꿈(데스크톱)로 둔다. 장애 시나리오는 버튼이 아니라 개발자 보기의 오류 주입으로만 다룬다.
- 4·5번(중복 쉼터 제목 줄, 무관 근거 ID)은 백엔드 판단 영역이라 손대지 않는다. 화면은 받은 문장을 그대로 그린다.
- 스크린샷은 headless Chrome으로 1280×800 캡처해 `doc/internal/screens/6_*.png`로 저장한다.

## 8. 구현 중 추가 지시 (2026-10-21)
- 정거장 아래에 세부 노드를 지나가는 순서대로 한 줄씩: 판단(의도 파악·지역 확정·계획) / 근거(조회·판정) / 빠른 답(기본 요약) / 최종 답(작성·검증·재작성·고정 양식 전환). `judgement`·`evidence`·`quick`은 모두 `judge` 노드 안에서 나오므로 조회·판정을 근거 정거장에 둔다.
- AI 노드는 초록 원 `#0E7C66`(다크 `#3FB89A`), 코드 노드는 먹색 사각. **가정**: 계획은 ADR-018 이후 코드 규칙 표라 `plan.source`가 `rules`가 아닐 때만 초록. 의도 파악도 LLM이 실패해 규칙으로 대체되면 사각으로 바뀐다.
- 개발자 보기에는 노드별 소요 시간 숫자(노드 줄 오른쪽)와 오류 주입만. 데이터 모드·기준 시각 입력은 일반 화면으로 되돌림, 분기·의도 배지와 실행 정보 패널은 삭제(노드 줄·툴팁으로 대체).
- 판정 띠 제목에 재난 유형: 특보마다 한 줄("폭염경보 발효 중"), 경보 먼저·예고 뒤, 띠 색은 `judgement.level`(코드가 정한 가장 높은 등급). 정보 없음도 찾은 대상을 함께("폭염 특보 · 정보 없음", "차량 침수 시 탈출 요령 · 정보 없음").
