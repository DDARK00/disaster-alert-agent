# 도커 실행

```bash
cp .env.example .env      # 키 채우기 (이미 있으면 생략)
docker compose up --build # http://localhost:8080
```

| 컨테이너 | 역할 | 포트 | 받는 환경변수 |
|---|---|---|---|
| `mcp` | MCP 서버(Streamable HTTP, `/mcp`) | 8200 (내부) | 서비스키 3종, `DATA_MODE` |
| `backend` | FastAPI + LangGraph | 8100 (내부) | `MCP_URL`, `LLM_*`, `LANGSMITH_*` |
| `frontend` | nginx 정적 + `/api/` 프록시(SSE) | 8080 → 80 | – |

- 서비스키는 `mcp`에만 전달한다. 백엔드·프론트에는 가지 않는다.
- `./data`를 `mcp`에 마운트한다 → fixture 추가·live 캡처가 호스트에 남는다(live 캡처는 gitignore).
- LLM을 호스트 Ollama로 쓰려면 `.env`에 `LLM_BACKEND=openai_compat`, `LLM_MODEL=qwen3:8b`(또는 9b 등). 컨테이너 안에서는 `host.docker.internal:11434`로 호스트에 닿는다. Linux는 `OLLAMA_HOST=0.0.0.0`이 필요할 수 있다. 모델 이름만 바꾸면 되고 코드는 그대로다.
- 호스팅 API(OpenAI 호환)는 `LLM_BASE_URL_DOCKER`, `LLM_MODEL`, `LLM_API_KEY`만 바꾼다.

## 검증 상태 (2026-10-20, macOS · Docker Desktop · Ollama 0.32.9)
- 확인함
  - `docker compose up --build` 3컨테이너 기동, 헬스체크 healthy, `localhost:8080` 200, `/api/health` `status: ok`. (첫 실행 403 → T-019)
  - SSE가 nginx를 통과해 버퍼링 없이 흐름: qwen3:8b에서 `judgement` 약 3초, `final` 약 18초에 각각 도착.
  - 호스트 Ollama(qwen3:8b) 호출: `host.docker.internal:11434`로 연결됨. 사고 출력 끄기는 `reasoning_effort=none` 필요(T-020).
  - 시나리오 러너: `.venv/bin/python eval/run_scenarios.py [--live]` — replay 8개 + live 1개 모두 합격 기준 통과(fake·qwen3:8b).
  - LangSmith: `LANGSMITH_TRACING=true`로 `disaster-advisor`에 `disaster_chat` 트레이스, 노드·LLM·MCP 도구 span 확인(T-022).
  - live: 실제 기상특보·재난문자 호출 성공(`resultCode=00`, 캡처에 키 없음). 60일 초과 `as_of`로 `resultCode=99`를 유도하면 `unknown`("정보 없음")으로 떨어짐.
- 실행 팁: `.env`를 바꾸지 않고 셸에서 덮어쓸 수 있다 — `LLM_BACKEND=openai_compat LANGSMITH_TRACING=true docker compose up -d --build`.
- 미확인: Linux 호스트의 Ollama 접근(`OLLAMA_HOST=0.0.0.0`), 호스팅 OpenAI 호환 API.
