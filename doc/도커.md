# 도커 실행

```bash
cp .env.example .env      # 키 채우기 (이미 있으면 생략)
docker compose up --build # http://localhost:8080
```

| 컨테이너 | 역할 | 포트 | 받는 환경변수 |
|---|---|---|---|
| `mcp` | MCP 서버(Streamable HTTP, `/mcp`) | 8200 (내부) | 서비스키 3종, `DATA_MODE` |
| `backend` | FastAPI + LangGraph | 8100 (내부) | `MCP_URL`, `LLM_*`, `LANGSMITH_*` |
| `frontend` | nginx 정적 + `/api/` 프록시(SSE) | 8080 → 80 | – |

- 서비스키는 `mcp`에만 전달한다. 백엔드·프론트에는 가지 않는다.
- `./data`를 `mcp`에 마운트한다 → fixture 추가·live 캡처가 호스트에 남는다(live 캡처는 gitignore).
- LLM을 호스트 Ollama로 쓰려면 `.env`에 `LLM_BACKEND=openai_compat`, `LLM_MODEL=qwen3:8b`(또는 9b 등). 컨테이너 안에서는 `host.docker.internal:11434`로 호스트에 닿는다. Linux는 `OLLAMA_HOST=0.0.0.0`이 필요할 수 있다. 모델 이름만 바꾸면 되고 코드는 그대로다.
- 호스팅 API(OpenAI 호환)는 `LLM_BASE_URL_DOCKER`, `LLM_MODEL`, `LLM_API_KEY`만 바꾼다.

## 검증 상태 (정직하게)
- 확인함: compose YAML 구조, 서비스키 최소 권한, MCP를 Streamable HTTP로 띄우고 백엔드가 `MCP_URL`로 붙어 SSE까지 도는 것(도커 없이 프로세스로).
- **확인 못 함**: `docker build`/`docker compose up` 자체(이 작업 환경에 도커가 없음), nginx 설정 문법, Ollama 실모델 호출. 첫 실행에서 문제가 나면 `doc/트러블슈팅.md`에 기록한다.
