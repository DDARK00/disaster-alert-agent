## T-026. 조회 창 이전에 발표된 특보를 '확인된 위험 정보 없음'으로 놓침 (평가 세트가 발견)
- 증상: 평가 항목 `gj_tropical_before_window` — "광주광역시 열대야 어때?" @08-22 12:00 → `none`. 원본 이벤트상 광주서부 열대야주의보는 창(08-21~) 안 첫 이벤트가 08-23 16:00 **해제**이므로 08-22에는 발효 중이었다. 위험 놓침(recall) 사례.
- 원인: `fold_alerts`가 as_of 이전 발표 이벤트만 접는다. 발표가 창 이전이면 as_of 시점에 그 (구역, 종류)의 이벤트가 하나도 없어 '없음'이 된다. live도 59일 창 밖에서 발표된 장기 특보는 같은 한계가 있다(API 60일 제약, T-013) — 해제 전이면 이벤트가 없어 감지 불가.
- 조치: 창 안 첫 이벤트가 as_of 이후 효력의 해제면 as_of에 발효 중으로 접는다(`inferred=True`, `since=None`). 문구는 "발효 시각은 조회 범위 이전 — 이후 해제 발표로 확인". as_of에 몰랐을 해제 예정 시각은 표시하지 않는다.
- 영향: 광주동부 열대야도 창 안 첫 이벤트가 09-02 해제 → 08-22~09-02 발효 중으로 바뀜(`ambiguous_rain` 근거 1건 추가, 레벨 동일). 평가 기대값 `amb_mixed`도 사람이 광주서부만 보고 잘못 정했던 것을 고침.
- 남은 한계: live에서 59일보다 오래 이어지는 특보는 여전히 보이지 않는다(해제 전엔 이벤트 없음). `getPwnStatus`(현재 특보 현황) 보조 조회가 후보.
- 상태: 해결(replay), live 한계는 미해결(확인 필요)

## T-025. Kakao 키워드 1위가 다른 지역이거나 통합특별시 이름으로 옴 → 지역 결정의 보조 신호로만 사용

## T-019. 도커 프론트 `localhost:8080/`이 403 Forbidden
- 증상: `docker compose up --build`는 성공, `/api/health`는 `ok`인데 `/`만 403. nginx 로그 `open() "/usr/share/nginx/html/index.html" failed (13: Permission denied)`.
- 원인: 호스트의 `frontend/index.html` 권한이 `600`(클라우드 세션에서 생성). `COPY`는 권한을 그대로 가져가고 nginx 워커(`nginx` 사용자)는 root 소유 600 파일을 못 읽는다. git은 644로만 저장하므로 새로 clone하면 재현되지 않는 환경 의존 문제.
- 조치: `frontend/Dockerfile`에서 `COPY --chmod=644`로 권한 고정. (mcp/backend는 `chown -R app`이라 영향 없음)
- 상태: 해결

## T-016. LangGraph `get_stream_writer()`가 Python 3.10 async에서 동작하지 않음
- 증상: 노드에서 `writer(...)` 호출 시 `RuntimeError: Called get_config outside of a runnable context`. 개발 머신은 3.10, 컨테이너는 3.12라 환경에 따라 달라질 수 있음.
- 원인: 3.11 미만의 asyncio는 컨텍스트 변수를 태스크로 전파하지 않아 `get_config()`가 실패.
- 조치: LangGraph writer를 쓰지 않고, 요청마다 `config["configurable"]["emit"]` 콜백을 넘기는 방식으로 변경(서버는 `asyncio.Queue`, 테스트는 `list.append`). 노드는 `config: RunnableConfig` 인자를 받아 콜백을 꺼낸다. 버전과 무관하게 동작.
- 상태: 해결

## T-015. stdio MCP 서버 서브프로세스가 부모의 환경변수를 물려받지 않음
- 증상: 셸에서 `DATA_MODE=live`와 `.env`를 export하고 클라이언트를 띄웠는데 서버는 replay 모드로 동작.
- 원인: fastmcp stdio 전송은 서브프로세스 환경을 부모와 같게 넘기지 않는다(`StdioTransport(env=...)`로 명시한 것만 전달). 문자열 경로로 서버를 지정하는 방식은 deprecated 경고도 낸다.
- 조치: 백엔드가 서버를 띄울 때 `StdioTransport(command=..., args=[...], env={"DATA_MODE": ...})`로 명시. 서비스키는 서버가 프로젝트 루트 `.env`를 직접 읽는다(환경변수로 키를 넘기지 않음). 실습 코드(`mcp_client.py`)는 `env={**os.environ}`을 직접 넘기는 방식이라 같은 점에 주의.
- 상태: 해결

## T-014. 특보 발표코드(command)의 의미가 명세에 없어 일부는 가정으로 처리

- 효력 시각: `startTime`(발효), `endTime`(해제)은 `tmFc`(발표 시각)와 다를 수 있음. 예: 08-23 10:00 발표, 11:00 발효. 해제도 발표 후 나중에 효력. `as_of` 시점으로 `active` / `pending_start` / 해제 예고를 구분.
- 실데이터에서 창 시작 직후 첫 이벤트가 `7`(변경발표)로 시작하는 경우가 있음(이전 발표가 조회 창 밖) → 이벤트 하나만으로 상태를 세울 수 있게 처리.
- 상태: 우회(가정 명시)

## T-013. 기상특보 API의 숨은 제약: 조회기간 60일, 오류가 HTTP 200으로 옴
- 증상 1: `fromTmFc=20260101`로 호출하면 HTTP 200인데 `resultCode="99"`, `"최대 조회 기간은 오늘 기준으로 60일 전까지입니다."`. 명세에는 없음(과거 이력이 2004년부터 있다는 소개 문구와 불일치).
- 증상 2: 정상 응답인데 `totalCount`가 0이고 `item`은 6건 들어 있음 → `totalCount`를 신뢰하지 않고 `item` 길이를 사용.
- 증상 3: 상위 구역(`L1130000`, `L1130100`)은 `resultCode="03"`(NO_DATA). 특보는 말단 구역(`광주서부 L1130110`, `광주동부 L1130120`)으로만 발표됨.
- 증상 4: `stnId` 없이 호출하면 전부 `stnId=108`(통합 발표)로 옴.
- 조치: 래퍼가 `resultCode`를 `meta.api_ok`로 기록(HTTP 상태만 믿지 않음). 60일을 넘는 과거는 라이브로 못 가져오므로 **지금 수집해 둔 fixture가 replay 원본**이다. 실제 사례는 2026-08-23~09-03(광주 폭염·열대야·호우)과 2026-10-18(경기 강풍·호우). 이후 더 필요하면 60일이 지나기 전에 추가 수집.
- 상태: 해결(수집 완료), 재수집은 기한 있음

## T-003. 기상특보 명세 내부 불일치
- 증상 1: 요청 예제에 `warninType=6` 오타. 파라미터 표는 `warningType`.
- 증상 2: XML 예제 `resultCode`는 `0`, 응답 명세 표는 `00`.
- 증상 3: 서비스 URL이 `http://` (전송 암호화 없음 표기).
- 호출 결과: JSON 응답의 `resultCode`는 `"00"`, `http://` 호출 성공(HTTPS는 미시험). `tmFc` 등 시각이 JSON에서는 숫자(int), `command`/`cancel`은 문자열, `warnVar`/`warnStress`는 숫자 → 어댑터에서 타입 정규화 필요.
- 조치: 파라미터는 표기준(`warningType`)으로 호출하고 응답이 무시되면 오타 쪽도 시험. `resultCode`는 `0`/`00` 모두 정상으로 처리. HTTPS 가능 여부는 호출로 확인하고, 어떤 경우든 **요청 URL을 로그·fixture에 저장할 때 `serviceKey`를 제거**.
- 상태: 미해결(확인 필요)
