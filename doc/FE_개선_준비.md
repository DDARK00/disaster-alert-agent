# 프론트·문구 개선 준비 (구현은 코드 세션에서, 지금은 준비만)

작성 2026-10-20. 근거: 실제 응답 화면에서 나온 지적(오류 원인 불명, 방어적 문구, 구역 코드 노출). 코드는 수정하지 않았다.

## 1. 검증기와의 연결 (문구를 바꿀 때 지켜야 할 것)
- 문구는 `prompts/messages.yaml` 한 곳에서 정의되고, 검증기는 `markers`의 조각(`no_info`, `no_risk`, `no_guarantee`, `official`, `emergency_call`)이 답변에 있는지로 검사한다.
- 문구를 바꾸면 **markers도 같이 바꾸고**, 기동 시 검사(`config/catalog.py`)와 테스트를 통과시킨다. 검증기 규칙을 느슨하게 하는 방향의 변경은 하지 않는다.
- 금지 표현("안전합니다" 류)은 그대로 유지한다. 둥글게 하되 안전을 단정하지 않는다.

## 2. 오류 원인별 사용자 문구 (제안)
| 원인 | 사용자에게 | 개발자 상세(접기) |
|---|---|---|
| 외부 API 응답 오류 (resultCode 등) | 기상특보 **정보 없음** — 지금은 불러오지 못했습니다. 잠시 후 다시 시도하거나 기상청에서 직접 확인해 주세요. | HTTP 상태, resultCode, 어느 소스 |
| 인증·키 오류 | 서비스 점검 중이라 **정보 없음**입니다. | 키 미설정/거부 |
| 호출 한도 | 요청이 많아 **정보 없음**입니다. 잠시 후 다시 시도해 주세요. | 한도 초과 |
| 시간 초과·네트워크 | 응답이 늦어 **정보 없음**입니다. 다시 시도해 주세요. | 타임아웃, 연결 실패 |
| MCP 서버 불가 | 서비스 연결 문제로 **정보 없음**입니다. | MCP URL, 예외 이름 |
| 응답 파싱 오류 | 데이터를 읽지 못해 **정보 없음**입니다. | 파싱 위치 |
| replay 범위 밖 | 시연 데이터가 이 시각을 덮지 않아 **정보 없음**입니다. 실시간 모드로 확인해 보세요. | replay 범위 |
- 화면에 영어 상태값(`no_coverage`, `failed`)을 그대로 보이지 않는다. 개발자 상세는 "자세히 보기"에만.
- 전제: 백엔드가 원인 분류 코드를 내려 줘야 한다(미흡점 1번, 코드 세션).

## 3. 결과 문구 (제안, 표준 조각 유지)
- 위험 정보 없음: `확인된 위험 정보 없음 (기준 {시각}, {지역 이름}). 상황은 수시로 바뀔 수 있으니 공식 채널도 함께 확인해 주세요.` → `no_guarantee` 조각("안전을 보장")을 쓰지 않는 안이므로 markers 수정이 필요.
- 특보 발효: `{등급} 발효 중 (기준 {시각})` 그대로.
- 실패: 2번 표.

## 4. 면책 배너 (제안)
지금: `공식 경보가 아닙니다. 위급할 때는 119·112, 공식 채널(기상청, 재난문자, 국민재난안전포털)을 확인하세요.`
- 문제: 재난문자는 공식 정보인데 "공식 경보 아님"이 맨 위에 상시 노출돼 사용성이 떨어진다.
- 안 A: `공식 데이터(기상청·행정안전부)를 정리한 안내입니다. 공식 경보를 대신하지 않으며, 위급하면 즉시 119·112.`
- 안 B(짧게): `공식 경보를 대신하지 않습니다 · 위급하면 119·112 · 공식 채널에서 최종 확인`
- 검증기 조각 `official`("공식 경보")과 `emergency_call`("119")을 모두 포함하는 안이다. 상시 배너와 답변 본문의 면책이 중복되지 않게 한쪽만 남기는 것도 후보(본문 면책은 검증 규칙이므로 변경 시 규칙 협의).

## 5. 표시 개선
- 구역 코드(L1013400 등) 대신 지역 이름을 보여 주고 코드는 "자세히 보기"에만.
- 지역이 여러 곳(모호한 "광주")이면 탭 또는 카드 나란히로 구분.
- 판정 카드 위에 한 줄 요약(등급·기준 시각·지역), 그 아래 "지금 할 일 / 미리 할 일" 순(행동요령 구조화 후).
- 단계 표시(분기·의도·지역…)는 개발자용이므로 접어 두거나 개발자 모드로.
- 응답 대기: 단계별 진행 표시는 유지하되 지연 원인(LLM 대기)이 보이게.

## 6. 시연용과 배포용의 차이 (HTML 한 장이 시연에 적합한 이유와 한계)
| 항목 | 시연 | 배포 시 필요 |
|---|---|---|
| 형태 | HTML 한 장, 바닐라 JS | 빌드·번들, 컴포넌트화는 선택(규모가 작으면 한 장도 가능) |
| 인증·남용 방지 | 없음 | 속도 제한, 봇 방지, 필요 시 로그인 |
| 위치 | 시나리오 버튼, 텍스트 입력 | 브라우저 위치 동의 흐름(시군구 단위로 반올림, 저장 안 함) |
| 접근성 | 기본 | 스크린리더, 대비, 키보드 조작 |
| 모바일 | 최소 | 모바일 우선 레이아웃, 느린 망에서의 로딩 |
| 오류 처리 | 문구 일부 | 원인별 문구, 재시도 버튼 |
| 데이터 모드 | replay/live 선택 노출 | 일반 사용자에게는 live만, 시연 모드는 숨김 |
| 개인정보 | 로그에 질문 저장 가능 | 질문·위치 로그 최소화, LangSmith 마스킹 |
| 관측 | 개발자 단계 표시 | 오류율·지연 모니터링 |
| 도메인·HTTPS | 로컬 | HTTPS, CORS 제한, 키 비노출 확인 |
